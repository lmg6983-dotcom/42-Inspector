# inspector42

검사 규칙이 전부 `inspector42.exe`에 내장되어 있다.
**소스를 읽지 말고, 검사 스크립트를 따로 작성하지 말고, 아래 명령만 실행한다.**

`K` 자리에 셸에 맞는 실행 경로를 넣는다:
- Bash: `"/c/Users/mklee/.gemini/config/skills/inspector42/bin/inspector42.exe"`
- PowerShell: `[Console]::OutputEncoding=[Text.Encoding]::UTF8; & "C:\Users\mklee\.gemini\config\skills\inspector42\bin\inspector42.exe"`

| 요청 | 명령 |
|---|---|
| 검사 (에이전트용) | `K --json "<파일>"` |
| 검사 (사람에게 그대로 보여줄 때) | `K "<파일>"` |
| `line` 위치 확인 | `K --dump-text "<파일>"` (줄 번호의 기준 텍스트. DOCX·HWP·HWPX는 문단 번호) |

- 파일: TXT(UTF-8·UTF-16·CP949) · DOCX · HWPX · HWP 5.0. 확장자가 아니라 내용으로 판별.
- `【청구항 1】` `【도면의 간단한 설명】` `【부호의 설명】` `【도 1】` 머리말로 섹션을 나눈다(`[청구항 1]`도 됨). 머리말이 없으면 글 전체를 청구항 하나(`claim: 0`)로 본다.
- 사용자가 준 파일은 그 경로에서 바로 읽는다. 변환본·복사본을 만들지 않는다.

## 출력 → 행동

종료 코드 `0` 지적 없음, `1` 지적 있음, `2` 사용법 오류·읽기 실패(`{"error": "..."}`를 그대로 전달).

```json
{"total": 3, "reports": [
  {"id": "particles", "title": "괄호 뒤 조사", "info": [],
   "problems": [{"message": "전극(20)는 → 전극(20)은", "claim": null, "line": 10,
                 "find": "전극(20)는", "replace": "전극(20)은"}]}
]}
```

- `find`/`replace`가 있는 지적(`particles`, `repeats`)만 그대로 치환해도 된다. 그래도 치환 전 해당 줄 문맥을 확인한다.
- 나머지(`replace: null`)는 판단이 필요하다. 문맥을 보고 고칠지 정하고, 권리범위·기술적 의미가 달라질 수 있으면 사용자에게 선택지를 준다.
- 모든 지적은 참고용이다. 오탐이면 고치지 않고 "오탐으로 보아 유지"라고 보고한다.

| id | 내용 |
|---|---|
| `antecedent` | `상기 X`의 X가 같은 청구항 앞부분이나 인용항에 나왔는지 |
| `numerals` | `이름(부호)`: 한 부호에 여러 이름, 한 이름에 여러 부호 |
| `repeats` | 1~3어절 바로 반복 (`투명 투명`) |
| `particles` | 괄호 뒤 조사 (`전극(20)는` → `전극(20)은`) |
| `figures` | 도면의 간단한 설명 ↔ 본문 ↔ 첨부 도면의 도면 번호 |
| `citations` | 없는/뒤 청구항 인용, 번호 누락, 택일적 기재, 다중→다중 인용 |
| `vague` | 청구항의 `약` `대략` `바람직` `예를 들어` `등` … |
| `sign_list` | `【부호의 설명】` ↔ 실제 쓰인 부호: 안 쓰인 부호, 목록에 없는 부호, 이름 불일치 |
| `claim_form` | 청구항이 마침표로 끝나는 한 문장인지, 청구항 `이름(부호)`가 발명의 설명과 같은지 |
| `support` | 청구항 구성이 발명의 설명에 나오는지 (제42조 제4항 제1호) |

## 보고 형식

`id`별로 묶어 "지적 N건 → 수정 M건 / 판단 필요 K건 / 오탐 L건"으로 요약하고, 판단 필요 항목만 원문 위치와 함께 나열한다.
